# @huanlin/dsh-plugin-ya-workspace-sidebar · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 上游范围：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)，234 commits。
> 本文所有 alpha2 证据均来自只读 git 命令（`git -C D:/Projects/deepseek-harness/dsh show/grep/diff dsh-v0.1.2-alpha.2 …`），未修改 dsh/ 任何文件。

## 结论

**✅ 直接可升 —— 插件源码零改动即可在 alpha.2 上运行。**

一句话理由：本插件刻意没有使用任何 alpha.2 中被改名/重构的 API（`connectionGeneration`、`client-connection`、`ClientResult/ClientFailure`、目录选择器失败码等全部未被引用），其消费的全部 dsh 面（ui-slots 契约、workspace/session Controller client 契约、primitives、`uiWorkspace` 服务位、`session/event` Host 事件、projection cache 遗留单文件引导路径）在 alpha.2 中逐项核实**原样存在**；唯一必要的动作是上游完成源码升级后**重建 `lib/`** 让类型与产物对齐 alpha.2。需要适配的只有两件可选项：peerDependencies 版本范围对齐（非必须，semver 已兼容）与错误提示文案中的失败码展示变化（纯观感）。

## 迁移步骤

**核心结论：本插件无需任何源码改动。** 以下按「人类升级 dsh → 插件侧对齐」顺序执行。

1. **（上游，由人类按 SOP 完成）升级运行中的 dsh 源码**
   `~/.dsh/source/current` 执行 `git pull --ff-only` → `pnpm install --prefer-offline` → `pnpm run build`（前台 ≥600000ms）。本插件消费的 15 个 link 目标包在 alpha.2 全部存在，`pnpm install` 后 `Cannot find package` 不会因本插件产生。

2. **插件源码：无需改动**（明确声明：`src/`、`tests/`、`cordis.patch.yml`、`tsdown.config.ts`、`package.json` 均无需修改）。
   关键对照：插件 client 注入列表与官方 alpha.2 ui-workspace 的 inject 列表**逐项相同**（官方恰好在本版删掉了 `'connection'`，与本插件现状收敛一致）；`hooks` 注入只含 `directoryFlow`，不含被更名的 `connectionGeneration`。

3. **（可选，建议）对齐 peerDependencies 版本范围**：把 `package.json` 中 15 个 `@deepseek-ai/*` peer 从 `^0.1.2-alpha.1` 提到 `^0.1.2-alpha.2`（16 处含 react 共 15+1 个 peer，`peerDependenciesMeta` 不动）。**不是必须**：semver 上 `^0.1.2-alpha.1`（= `>=0.1.2-alpha.1 <0.2.0`，同元组预发布规则）已接受 `0.1.2-alpha.2`；提升只为版本语义对齐。改动后记得**不要**提交到上游仓库的是本机 `link:` 路径（现有 `link:C:/Users/Administrator/.dsh/source/current/...` 是本机补丁，继续保持不提交）。

4. **重建 `lib/`**（在 `D:/Projects/deepseek-harness/ya-workspace-sidebar`）：
   ```powershell
   pnpm install          # 刷新 link: 指向的 alpha.2 包（typecheck/构建解析新类型）
   pnpm run typecheck
   pnpm test
   pnpm run build        # tsdown（host+client CJS 包）+ tsc 产物 lib/types/
   ```
   本仓库 build 脚本无 `rm -rf`，无 Windows 坑；`lib/` 为预构建入库产物，重建后随仓库提交。
   > link: 引用下，`lib/` 重建即对 profile 生效，无需 `dsh plugin update`（那是 github: 引用的动作，对 link 无效，勿跑）。

5. **profile 端验证**（link: 引用）：确认 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-ya-workspace-sidebar/lib/client.js` 时间戳已更新；然后**重启 `dsh web` 进程 + 浏览器硬刷新（Ctrl+Shift+R）**（DSH web 前端缓存模块表，硬刷新前旧 bundle 仍会被复用）。

6. **对外发布走 huanlinoto 发布 SOP**（本次零改动可只发 peer 对齐版，或跳过）：
   ```powershell
   Push-Location D:/Projects/deepseek-harness/ya-workspace-sidebar
   ```

## 升级后验证清单

前置：`dsh web` 已**重启**、浏览器已 **Ctrl+Shift+R** 硬刷新（以下每项都在此之后观察）。
